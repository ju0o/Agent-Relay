# WBS-1 + WBS-2 — Role graph/assignment config + RoleRuntimeAdapter interface (implementation spec; from issue #6; PM-authored)

## WBS-1 — durable role configuration (NOT Task truth)
- New module `src/roles/role-config.ts`: read/validate/write `{dataRoot}/_relay/roles/<project>.json` (schema `role-config.v1`), atomic write, per-project. Never stores Task/Run/Result data.
- `RoleAssignment` = { roleId: 'pm'|'builder'|'qa'|'architect', runtimeAdapterId: string, provider?: string, model?: string, workspace: { project: string, workspaceRoot: string }, sessionPolicy: 'persistent'|'per-task', permissionProfile: 'read-only'|'write-workspace'|'shell', capabilityRequirements: RoleCapabilityFlags (partial), zeroExtraBilling: true (must be true in V1; false → INVALID), fallbackChain: string[] (adapter ids), enabled: boolean }.
- `RoleGraphEdge` = { from: roleId|'owner', to: roleId|'owner', envelope: 'TASK_CONTRACT'|'RESULT'|'CHANGES'|'PASS'|'BLOCKED_GATE'|'NEXT_TASK'|'OWNER_REQUIRED' }; V1 default edges exactly: PM→Builder TASK_CONTRACT; Builder→QA RESULT; QA→Builder CHANGES; QA→PM PASS/BLOCKED_GATE; PM→Builder CHANGES/NEXT_TASK; PM→Owner OWNER_REQUIRED. `defaultV1RoleGraph()` returns them; `validateRoleGraph()` rejects unknown roles/envelopes/duplicates.
- `validateRoleConfig()` also enforces: each enabled role has an adapter; capabilityRequirements ⊆ adapter capabilities (checked in WBS-2 via a registry lookup function passed in); pm.permissionProfile must be 'read-only' in V1.

## WBS-2 — command-side RoleRuntimeAdapter (do NOT change AgentAdapter observation semantics)
- New `src/integrations/core/role-runtime.ts`: `RoleCapabilityFlags` = { persistentSession, structuredInput, structuredOutput, readWorkspace, writeWorkspace, shell, subscriptionAuth, freeTier } (booleans). `RoleRuntimeAdapter` interface: `id`, `health(): Promise<{ok, detail?}>`, `capabilities(): RoleCapabilityFlags`, `authMode(): { mode: 'oauth-subscription'|'existing-plan-key'|'free'|'unknown', provider?: string }` (never secrets), `ensureSession({roleId, project, sessionPolicy, sessionKey}) → { sessionId, created }`, `send(sessionId, envelope: InputEnvelope) → { requestId }`, `collect(sessionId, requestId, {timeoutMs}) → { text, structured?: unknown, raw?: unknown, tokens?, cost? }`, `interrupt(sessionId)`, `resume(sessionId) → { ok }`, `sessionIdentity(sessionId) → { adapterId, sessionId, provider?, model? }`.
- `InputEnvelope` = { kind: 'PM_BOOTSTRAP'|'PM_FINAL_GATE'|'QA_PACKET'|'TASK_CONTRACT'|'CHANGES', schemaVersion: string, contractHash?: string, contextHash: string, body: string (rendered text), attachments?: [] } — text-rendered for the model; structured output parsed by the caller with strict schema (WBS-5/7/8 own the schemas).
- `src/integrations/core/role-runtime-registry.ts`: register adapters by id; `assertRoleSatisfiable(assignment, adapter)` throws ROLE_CAPABILITY_MISMATCH listing missing flags.
- Durable session bookkeeping: `{dataRoot}/_relay/role-sessions/<project>/<roleId>.json` = { adapterId, sessionId, createdAt, lastUsedAt } (so a Relay restart can `resume`). Not Task truth.
